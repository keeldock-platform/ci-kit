# Publication policy

Before applying an owner handoff, run `python3 -B tests/policy/handoff_consistency.py --root . --settings /absolute/path/settings.json --callers /absolute/path/caller-templates` against clean signed production and caller snapshots. Generate the external settings and callers after the final kit commit; the check reads actual Git HEAD without an override. It checks all active settings/registration/diagnostics pins, caller workflow inputs and lock pins, every workflow and composite dependency against each parent/child exact allowlist, child unions, and recorded legacy consumers. Historical exact allowlist refs remain for coexistence. A later kit commit requires regenerating the handoff. The owner-only settings and inventory stay outside the public repository. Regression tests run in the ordinary Python integration suite.

`public_content.py` scans tracked paths, file contents, index blobs and every outgoing commit using an externally supplied JSON policy. The policy has `schema_version: 1` and nonempty `terms` and `markers` arrays; keep it outside the public checkout. Missing policy, unsupported content or any match fails. Output contains a fixed result; an optional private report stays outside the checkout.

Run the scan before publishing. `pre-push` is the candidate-branch publishing hook; it never dispatches workflows. Synthetic tests use invented terms only.

`workflow_lint.py` passes published YAML through actionlint with a lint-only compatibility projection for the pinned validator: root `cache-mode: none` becomes a blank line, and native `$/` composite references use the same local action metadata. Runtime YAML is unchanged; other values and diagnostics remain errors. This handles documented provider syntax newer than actionlint 1.7.12. Native action locks independently verify action identity.

Workflow discovery includes every YAML workflow and tracked action definition, including retained caller automation. The structural `legacy-caller` role permits the existing `kit`, `ci`, and `core-ci` hierarchy and conventional workflow names without a fixed-file admission list or content exemptions; it does not impose new ownership authority on migrated callers. Strict kit and caller ownership rules remain unchanged. The publication content check still scans the complete tree and outgoing history without a baseline exemption. The complete clean kit uses literal full-SHA actions inside same-revision composites and verifies their native locks. This supplies immutable execution when native enforcement is unavailable; deployment still requires independent review of the account controls. External reusable workflows use full-SHA refs. Native locks bind reviewed full commit SHAs and numeric identities; external reusable workflows use full-SHA refs.

`public_tree_scan.py` is a public-safe hosted scan of the complete tracked current tree, index, and bounded full commit history (up to `MAX_COMMITS`, refusing shallow or unborn repositories). It checks full credential shapes, encoded views and local user paths without private inputs or candidate execution. Its three binary fixture exceptions bind only prior published path/SHA256 pairs; changed or new binaries refuse. It is complementary to the mandatory private external-denylist prepublication scan across full outgoing history, refs, metadata and content. The hosted generic scan does not replace that gate and cannot prove the absence of organization-specific private identifiers.

`workflow_lock.py` runs native `gh-actions-lock --verify` across the complete caller repository. Every error and warning refuses except `sha-as-ref` for a literal lower-case full commit SHA: the separately required immutable-reference check enforces that stronger execution identity. The lock tool recommends a symbolic tag for traceability, but switching execution to tags would remove the independent SHA boundary. Missing, malformed, stale, moved, unreachable or mismatched lock entries still refuse. Kit policy retains its existing strict native check.
